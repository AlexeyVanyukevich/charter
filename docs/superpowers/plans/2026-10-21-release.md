# Cutting a release — implementation plan

Spec: `docs/superpowers/specs/2026-10-21-release-design.md`. Each task writes its check first,
sees it fail, then builds until `./check` passes, and ends in one commit holding the check and
the code.

Two backlog entries touch this slice and are left there knowingly. "No release reaches the
private registry" is outside it (spec §7). "`./check 40` can fail on a session that read
nothing" may fail a run of task 6's live check too. A failure is rerun once and reported, not
fixed here.

## Task 1 — probe a skill written by the first session's hook

Spec §5. In a temporary consumer with no `.claude/skills/`, a `SessionStart` hook writes
`.claude/skills/charter-probe/SKILL.md` and a `.gitignore` of `*` beside it. Then, with Claude Code
2.1.287:

- `claude -p "/charter-probe"` in that first session: does it run?
- the same in a second session;
- the skill listed to the model in each.

The result decides task 6's live check and the README's line. Nothing is committed; the answer
goes into this plan, under this task, before task 2 starts.

## Task 2 — `sync` mirrors `core`'s skills

- `checks/75-sync.sh`: the test kit gains `core/skills/probe/SKILL.md`; the cases of spec §4.
  See them fail.
- `bin/sync.mjs`: `plan` adds each `core/skills/<name>/` file under
  `.claude/skills/charter-<name>/`, with a `.gitignore` of `*`; `sync` removes symlinks there as
  it does in the rules mirror; `prune` deletes `charter-*` directories the kit no longer ships
  and touches nothing else in `.claude/skills/`.
- Commit: `feat(sync): mirror core's skills into .claude/skills`

## Task 3 — `charter release` shows the gates, the commits and the proposal

- `checks/85-release.sh`, new: a repository in a temporary directory with a bare `origin`; the
  proposal table and the gates table of spec §4. See them fail.
- `bin/release.mjs`, new: the gates, the commit list, the proposal. `bin/charter.mjs` dispatches
  `release` and its usage line names it. `charter.json`'s `release` key is read, and refused when
  it is not an object, `verify` not a string, or `files` not a list of strings.
- Commit: `feat(release): show the gates, the commits and the proposed version`

## Task 4 — `charter release notes`
