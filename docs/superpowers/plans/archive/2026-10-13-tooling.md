# A commit-msg hook and a lint config per section — implementation plan

Spec: `docs/superpowers/specs/2026-10-13-tooling-design.md`. Each task writes its check first,
sees it fail, then builds until `./check` passes, and ends in one commit holding the check and
the code.

## Task 1 — the hook

- `checks/80-commit-msg.sh`: the dataset of messages, run through
  `common/hooks/commit-msg` directly; every row names its expected result and, for a refusal,
  the words the refusal must contain.
- `common/hooks/commit-msg`: the checks of spec §3, in that order, each refusal naming itself.
- Commit: `feat: refuse a commit message that breaks the commit rule`

## Task 2 — installing it

- `checks/50-lib.sh`: `need_hooks` joins the defined functions.
- `checks/80-commit-msg.sh`: the `need_hooks` cases of spec §6, and the end-to-end commit in a
  scratch consumer built from `npm pack`.
- `checks/70-init.sh`: `init common` in a git repository writes the hook; `init ui` does not.
- `common/lib.sh`: `need_hooks`, per spec §4. `bin/dev-kit.mjs`: run it after `need_plugins`
  when `common` is named.
- Commit: `feat(lib): install the kit's commit-msg hook`

## Task 3 — the lint configs

- Fixture: `oxlint` and `oxlint-tsgolint` as devDependencies; `tests/fixture/lint/`, one small
  file per case, with a `tsconfig.json` covering them for the type-aware rules.
- `checks/90-lint.sh`: the dataset of spec §6, plus the run without `oxlint-tsgolint`.
- `oxlint.json` in `common`, `backend`, `ui`, `testing`, per spec §5.
- Commit: `feat: add a lint config to each section`

## Task 4 — documentation

- README: "Commit messages" and "Lint" under "The modules", with the table of rules turned off
  and the findings to expect on adoption; `need_hooks` in the `./run` list and example; the
  Sections table.
- `docs/backlog.md`: delete "Rules a tool could enforce are enforced only by prose".
- Commit: `docs: document the commit-msg hook and the lint configs`
- Move this plan to `archive/`. Commit: `docs: archive the tooling plan`

The release, 2.4.0, follows the merge to `main`.
