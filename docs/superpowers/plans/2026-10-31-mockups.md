# Mockups before UI code — implementation plan

Spec: `docs/superpowers/specs/2026-10-31-mockups-design.md`. Each task writes its check first,
sees it fail, then builds until `./check` passes, and ends in one commit holding the check and
the code. The branch is `feat/mockups`, on `main`.

Open issues read before planning: "`./check 40` can fail on a session that read nothing, and
hides why" (#43) touches the live session task 2 extends, and "`./check 70` prints the root
hook's backlog rule into the suite's output" (#47) the suite task 3 extends. Both are taken
into the plan, first, so the checks this slice extends are sound before it does. No other open
issue touches `sync`, skills or plugins.

## Task A — check 40 says what a session answered when it read nothing

- `checks/40-rules.sh`, `session()`: the "asked to read … the session did not" failure prints
  `$answer` before what the transcript shows, as #43 asks. No retry: whether one is honest
  follows from what the next failure prints.
- Commit: `test(rules): print a session's answer when it read nothing, fixes #43`

## Task B — check 70 captures what the root hook prints

- `checks/70-init.sh`: the run with the kit installed captures the hook's stdout, and its first
  line must be the file form's header, "charter: this project keeps its backlog in
  docs/backlog.md. core's backlog rule follows." Nothing reaches the suite's output.
- Commit: `test(init): check what the root hook prints, fixes #47`

## Task 1 — `sync` mirrors the skills of the modules a project names

- `checks/75-sync.sh`: the made-up kit gains a probe skill under a domain. It is mirrored to
  `.claude/skills/charter-<name>/` when a workspace names the domain, is absent when none does,
  and is deleted once `charter.json` drops the module. `core`'s probe skill is tested as today.
- `checks/40-rules.sh`: the skill loop covers `core/skills`, `domains/*/skills` and
  `stacks/*/skills`; skill directory names are unique across the kit; the guard that fails when
  a module ships skills goes. The count stays 1.
- See them fail.
- `bin/sync.mjs`: `plan` collects the skills of `core` and of every module any workspace
  names, once, at the root; the header comment says so.
- Commit: `feat(sync): mirror the skills of the modules a project names`
