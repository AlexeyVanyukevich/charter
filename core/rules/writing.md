# Writing

Write for a reader who does not have your machine.

**Refer to other projects, people and accounts by their role, not their name** — "the reference
application", "the consuming project", "the older of the two". When a document has to tell
several apart, define the roles once near the top and use them throughout.

**Name something only when the name is load-bearing:** a package that must be installed, a file
that must be opened, a command that must run, an API that must be called. A rule saying "use
`typebox`, not `@sinclair/typebox`" is destroyed by removing the names; a sentence saying which
sibling directory a convention came from is not.

A name dates the document and keeps it private to the room it was written in; a role does not.

The rule governs names, not facts. Dates, versions, line counts and measurements are what make
a claim checkable — keep them.
